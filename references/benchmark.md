# benchmark.md —— 六道对抗测试与五家评分矩阵

这份文件是 `aigc-detox-lcw` 的**立论依据**。它记录：测了什么、每家考多少分、为什么最后选了这个、扔了那个。
没有这份记录，`SKILL.md` 里的每一条取舍就只是我的个人偏好。

---

## 零、先说三条必须知道的前提

1. **测的是"文本信号识别与改写能力"，不是"过检测率"。**
   本工具、以及五个前身，都不掌握任何平台的检测模型。这里所有数字都是我们自建语料的判对/判错，不是知网、维普、Turnitin 的分数。
2. **"六题全对"不等于最强。**
   五家里有一家（aigc-detector）六题全对，误差 0 分——但它是让模型自己读、自己评。
   换个模型、换个温度，分数就变。**它不可复现。** 详细见 §四。
3. **我自己犯过一次污染测试语料的错，并且改了结论。**
   经过见 §五。这条放在前面，是因为它影响了最终数字。

## 一、测试设计

### 1.1 语料（6 题，全部带人工标注真值）

| 编号 | 文件 | 内容性质 | 真值 | 设计意图 |
|---|---|---|---|---|
| T1 | `T1_blatant.txt` | 满配模板 AI：理论起笔 + 首先/其次/再次 + 此案例印证 + 综上所述 + 具有重要意义 | **high** | 送分题，考基本功 |
| T2 | `T2_human_trap.txt` | 真人写作：68 名学生 / 12 组 / 第 11 分钟 / 37 条消息 / 9 条，含一处"值得注意的是"、承认样本局限 | **low** | **抗误报陷阱**。只中一个模板词就判高分的，会在这一题翻车 |
| T3 | `T3_stealth.txt` | 隐身 AI：**零模板词**，8 句全部"主体 + 在/对某场景 + 需要/应当/影响/关注 + 抽象双名词并列" | **high** | **分水岭题**。没有节奏维度就必然漏判 |
| T4 | `T4_citation.txt` | 引用实验密集：ResNet-50 92.7% / YOLOv8 89.4% / p<0.05 n=1200 / 18.3ms / 11.6ms / [12][13,14] / mAP 0.814→0.762 / 失败案例 41% / 3.2% | **low** | **过度诊断陷阱**。"技术整洁 ≠ AI"，只会加分的会误判 |
| T5 | `T5_english.txt` | 英文 LLM 腔：In today's rapidly evolving / pivotal / It is important to note / Moreover / underscore / delve / paving the way / realm / cutting-edge / In conclusion | **high** | **能力边界题**。纯中文词表的直接无能力 |
| T6 | `T6_legit_summary.txt` | 含"综上所述"但数据扎实：96→141 分钟 / 7.4→1.2 小时 / 承认无法拆分归因 / 给出对照实验计划 | **low** | **判据矛盾题**。规则说"综上所述=AI"，但语境说不是 |

### 1.2 计分规则

以真值分三档（high / medium / low，clear 视为 low 的极端）为准：

| 判读结果 | 扣分 |
|---|---|
| 判对（落在真值档，或差半档但方向正确） | 0 |
| 差一档（high 判成 medium 之类） | +1 |
| 差两档（high 判成 low） | +2 |
| 明确无能力（UNSUPPORTED / 中英不分导致瞎判） | +3 |

**误差总分越低越好。** 满分 6 题，理想 0。

### 1.3 协议约束

`PROTOCOL.md` 强制三条，防止测评员作弊：

- 逐题独立判定，**不得看其他题的结论**
- **禁止读 `_bench/out/`**（防止看到别的 skill 的结果）
- **禁止读其他 skill 目录**（防止抄别家的判据）
- 必须指出**具体段落**，不能只说"整体偏高"
- 没这个能力就写 `UNSUPPORTED`，不许硬猜

## 三、逐家评语（含证据）

### 3.1 ai-check —— 误差 1，**采用为主干**

**它唯一错的地方**：T1 给了 risk 3，最高档没到。

**它对的地方（每条都是它赢的原因）**：

- **T3 靠机械阈值抓住**：`uniform = len(sentences) >= 4 and cv < 0.3`，T3 实测 CV **0.064**。
  这是五家里唯一一个不是靠"找词"发现隐身 AI 的。
- **T4 给出 miti 8 个缓解信号**：引用编号、实验指标、统计量、模型名、实验结果表述、限定取舍、领域方法细节、定量结果支撑。
  **误差 0，一篇硬核论文没被冤枉。**
- **T2 只给 risk 1（"值得注意的是"）**，配合 0 个缓解信号仍能判 low —— 说明它的风险项不轻易堆叠。
- **中英双语**：T5 英文正确给 risk 5（3 个模板 + 节奏 + LLM 高频词）。

**它的设计原则值得抄下来**：

> "The script does not score, does not output probability, and does not predict institutional AIGC results.
> It only produces deterministic textual signals."

**这是整份测评里唯一一家主动声明自己不算分的。** 恰恰是它最准。

### 3.2 aigc-detector —— 误差 0，**但不采用它的分数**

**表面成绩最漂亮**：六题全对，T7 都没有。

**为什么不能信**：它自己的 SELF-REPORT 写得很清楚——

> "该 skill 没有检测引擎，Step 2 全部依赖模型语义判读，
> 五维分值是我人工判读后给出的，**主观性明显、不可复现**。"
> "SKILL.md 里的参考阈值表（连接词密度 > 12%、被动 > 45%、TTR < 0.60、突发性 < 1.5x）
> **没有任何可执行的计算入口**，等同于该表未被实际使用。"

**它还有一个隐患**：T3（零连接词的隐身 AI）它给逻辑词密度 35 分（很低），
是靠"句式规整度 92 + 论证深度 90"把总分顶上去的。
**只要把连接词权重调高，它当场就会漏判 T3。** 全对是靠权重凑出来的，不是靠判据。

**结论**：借它的**五个维度名称**当人工诊断清单（句式规整度 / 逻辑词密度 / 语态特征 / 词汇多样性 / 论证深度），
**彻底不要它的 0–100 分和百分比**。

### 3.3 chinese-thesis-workbench —— 误差 7，**检测器不采用**

**三个致命缺陷**：

1. **T3 完全漏判**：`pattern_counts` 为空，判 clear。它只有 10 条中文正则，没有任何节奏维度。
2. **T5 中英不分**：英文文本判 clear。它不是"识别出英文不是 AI"，是压根没有英文规则。
3. **T1 只判 medium**：满配模板 AI 都不到 high。判级偏松——`classify(score)` 要 score ≥ 5 才 high，而一段塞一两个套句只到 3。

**但它有两样东西是全场最好的，不过跟"降 AI"无关**：

- **I 模板填充 / 格式贴近（9/10）**：`apply_textual_edits.py` 里的 `apply_template_copy_fill`、
  `clone_source_paragraph_after` 能保住 `pPr/rPr/sectPr`。
- **K 全流程状态机（9/10）**：14 步 Required Workflow + phase/status 双层状态。

**这两项是"写论文"能力，不是"降 AI"能力。**
本 skill 的定位是降 AI，硬塞进来会让工作流臃肿。
**保留在原 skill，让有整篇论文需求的用户去用它。**

### 3.4 humanizer-zh-academic —— 误差 5，**方法论采用，判据不采用**

**漏判 T3 是结构性的**：它 Step1 的 11 项 checklist 全是模板词触发项。
零模板词时最多只能命中 1 分，远低于 4 分阈值。
它自己其实写了"每句长度接近、节奏单一"是无魂写作特征，**但没写进计分表**。
这是"想到了但没落地"的典型。

**T5 明确 UNSUPPORTED**：纯中文词表，诚实但无能力。

**它还自带三个内部矛盾（测评员实测发现的）**：

1. `SKILL.md`（414 行）与 `SKILL_full.md`（554 行）两版并存，判据有出入
   （`SKILL_full` 的自检清单多一条"成语/口语"，模式 5 多一句"关键问题是如何"），
   **没有任何说明该加载哪一版**。
2. 硬约束表写"AI 高频词见模式 10 词表"，**词表实际在模式 11**（模式 10 是泛化结论）。编号自指错误。
3. 硬约束表只把"此案例 XX 了 / 由此可见"列为段末套句，
   但模式 7 的触发词含"综上所述"，两处自相矛盾。

**它的好，全在"怎么改"上，不在"怎么判"上**：

- **D 改写方法论深度 9/10**、**E 改写前后对照示例 10/10**：16 个模式每个都有对照。
- **F 文体差异化 9/10**：4 类文体 × 3 维（第一人称 / 口语化 / 破折号）。
- **M 噪声保留 9/10**：每千字留 2–3 处，首选并列句、次选"值得注意的是"，绝不保留"此案例印证了"。

**结论**：整章的 16 模式与改写手法全部并入，**Step1 的计分表废弃**，改用脚本的三层诊断。

### 3.5 aigc-down-skill —— 误差 5，**不并入正文**

**与 humanizer 同血缘**：`difflib.SequenceMatcher` 相似度 **76.0%**，前 100 行几乎逐字相同。
两个都保留（用户要求），但整合版只收一份。

**它比 humanizer 弱的地方**：

- **文体标定只有"毕业论文"一行**（humanizer 有 4 类）。
- **T4 判 `located: NONE`** —— 不是"识别出技术整洁不是 AI"，是根本没找到触发词。
- **T3 只给 1 分**：模式 15 要求"冒号连续 3 次 / 破折号一段 4 次"才触发，隐身 AI 不满足。

**它最严重的两个问题**：

1. **默认四步流程第一步要求用户提供 `.html` AIGC 检测报告**，
   再从中提取高 AIGC 率标注段落。纯文本输入根本走不通，要靠"说'直接改'或 ≤300 字"的豁免才跑得起来。
2. **目录里没有任何脚本**（只有 SKILL.md / README.md / LICENSE / .git），
   README 宣称的"智能解析检测报告"**没有实现**。

**结论**：作为 humanizer 的备份留档。整合版正文不采用它的任何独有内容。

## 四、"可复现的 1 分 优于 不可复现的 0 分"

这是整份测评里最重要的一句话，值得单独一节。

| | ai-check | aigc-detector |
|---|---|---|
| 误差 | 1 | **0** |
| 证据类型 | 确定性正则 + 阈值 | 模型读完 → 主观打分 |
| 同一输入跑两次 | **结果完全相同** | 可能不同 |
| 换个模型跑 | 不受影响 | **结果完全不同** |
| 用户能自己复现吗 | 能，跑脚本 | 不能 |
| 出错时能定位吗 | 能，指出哪条正则 | 不能，只能说"模型判断" |

**选 ai-check 的 1 分，不选 aigc-detector 的 0 分。**

理由很简单：我要交给用户的是**可以复核的东西**。
一个说"我读了一遍，觉得这段 77.3% 像 AI"的工具，
用户没法反驳、没法验证、没法在两篇论文之间做一致比较。

再看第二条独立证据：**T3**。
aigc-detector 给 77.3%，ai-check 给"触发「句式节奏过于均匀」，CV=0.064"。
前者是数字，后者是**理由**。用户拿着 CV=0.064 可以去量自己文档，拿着 77.3% 什么也做不了。

## 五、我自己犯的错：测试语料污染（必须说）

**这不是小疏忽，它一度让结论完全反过来。**

### 发生了什么

v1 的测试文件第一行带了标注标题，例如：

```
T3 隐身 AI（期望 high）
「平台在内容分发环节需要兼顾效率与公平」……
```

`split_sentences` 把标题那一行也当成正文句子，计入了句长统计。
结果 T3 的 8 句 24–30 字里混进了一句 20 字的标题，CV 从 **0.064 被抬到 0.337**，
越过了 0.30 的阈值 —— `uniformSentenceRhythm` 变成 `false`。

**我据此写下"两个检测器都漏掉了 T3"的错误结论。**

### 怎么发现的

我在核对 CV 数值时发现 T3 的 CV（0.337）竟然**低于** T1（0.402），
而 T3 明明是刻意写得句长高度一致的。这个反直觉促使我去看原始句长列表，才看到标题混在里面。

### 怎么修的

```bash
for f in T*_*.txt; do tail -n +2 "$f" > "${f%.txt}.clean.txt"; done
```

（第一次还错用了 `-n +3`，把正文也删了 —— 因为每个测试文件只有 2 行：标题行 + 正文行。）

### 干净文本重算（**所有对外数字以这一版为准**）

| 文本 | v1 污染版 CV | **v2 干净版 CV** |
|---|---|---|
| T3 隐身 AI | 0.337 ✗ | **0.064** |
| T5 英文 | 0.177 ✗ | **0.172** |
| T1 满配模板 | — | 0.402 |
| T2 真人 | — | 0.396 |
| T4 引用密集 | — | 0.383 |
| T6 合理总结 | — | 0.334 |

**结论反转**：ai-check 不是漏判 T3，而是**精准抓住了 T3**。

### 教训（写了进 `signals.md` §一）

> **喂给任何统计脚本的文本必须是纯正文。**
> 标题、编号、"期望值"这类标注混进去，会直接改变统计量。
> 而且污染不会报错——它会安静地给你一个看起来合理的错数字。

## 七、N 项为什么是本次最大的增量

五个前身的工作流全是 **扫描 → 改写 → 结束**。
**没有任何一家在改写后回头检查一次。**

我造了三份 DOCX 实测（`_bench/rewrite_test/`）：

**好改写**（把模板词都清了，看起来做得很好）

```
风险信号  3 → 1   (Δ −2)
模板短语  2 → 0
泛化套话  1 → 0
连接词密度 0.375 → 0.0
句长 CV   0.534 → 0.272   ← 问题在这
新引入风险 ['句式节奏过于均匀']
判定：WARN
```

**这次改写的 CV 从 0.534 压到 0.272，掉进了"句式节奏过于均匀"区间。**
它去掉了模板词，却顺手把文本改成了另一种机器味 —— 这正是 T3 那类隐身 AI 的特征。

**五个前身没有一个会告诉用户这件事。它们改完就收工。**

**坏改写**（把"68 名学生"改成"一批学生"，数字全抹掉）

```
判定：FAIL
丢失数字 ['11', '12', '37', '68']
```

这个靠改写器的护栏本来就能拦下，但**复检器提供了第二道网** ——
万一有人手工改完文件再来验，也能抓到。

**这就是 N 项的价值：它是唯一一个能发现"改坏了"的环节。**
前五个都只能发现"原文有问题"。

## 九、三条必须向用户说清楚的局限

1. **这是确定性文本信号，不是 AI 检出率。**
   本工具永远不会输出"AI 率 87%"，也不会声称对齐知网 / 维普 / Turnitin。
   任何声称能给出准确百分比的工具，都在骗人 —— 包括本测评里那些给百分比的前身。

2. **aigc-detector 六题全对不代表它更强。**
   它是让模型自读自评，换模型换温度就变。**看起来最准的那个，恰恰是最不可复现的。**
