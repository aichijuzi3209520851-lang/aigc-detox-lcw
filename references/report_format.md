# 报告版式规范（report_format）

`aigc_detox_lcw_scan.py report` 会生成三份产物，本文档说明它们各自装什么、字段怎么读、以及在什么情况下不能引用其中的数字。

---

## 一、产物清单

| 文件 | 用途 | 关键约束 |
|---|---|---|
| `aigc-detox-lcw-report-<时间戳>.html` | 人看的完整报告，可直接在浏览器打开 | 自包含，无外链，无脚本 |
| `aigc-detox-lcw-report-<时间戳>.pdf` | 打印 / 提交用 | 中文依赖系统字体，缺字体时 `pdfError` 非空但 HTML 仍可用 |
| `aigc-detox-lcw-summary-<时间戳>.json` | 机器读的汇总，供复检或归档比对 | 键名不含任何 `aiRate` 类字段 |

时间戳格式 `YYYYMMDD-HHMMSS`，同一次 `report` 调用生成的三份文件共用同一个时间戳，便于配对。

---

## 二、summary JSON 的字段

```json
{
  "assistantMarkedRatio": 0.2073,
  "flaggedRatio": 0.3023,
  "remainingRatio": 0.7927,
  "suspiciousChars": 305,
  "totalChars": 1009,
  "fragmentCount": 2,
  "htmlPath": "...",
  "pdfPath": "...",
  "pdfError": "",
  "reportPath": "...",
  "summaryPath": "..."
}
```

| 字段 | 含义 | 怎么读 |
|---|---|---|
| `assistantMarkedRatio` | 各片段「助手标注值 × 字数」的加权和 ÷ 总字数 | **不是 AI 检出率**。它表达的只是「按助手判定，全文有多大比例的文字被标了问题」 |
| `flaggedRatio` | 被标成 `suspicious` 或 `ai` 的片段字数占比 | 粒度更粗，只看「有没有被标」 |
| `remainingRatio` | `1 - assistantMarkedRatio` | 不是「人写作率」，只是补数 |
| `suspiciousChars` / `totalChars` | 分子分母 | 两个数都可以独立核对 |
| `pdfError` | PDF 渲染失败原因 | 非空时不要交付 PDF，改用 HTML |

**四个数字全部来自助手对每个片段的 `aigcValue` 标注，不存在任何模型推理或黑盒打分。** 换一个助手、换一次判断，这些数字就会变 —— 这正是它不能称为「AI 率」的原因。

---

## 三、HTML 报告的版面结构

自上而下六个区块：

1. **标题** —— 「aigc-detox-lcw 文本特征诊断报告」。
2. **元信息栅格** —— 生成时间 / 来源文档 / 作者 / 诊断类型 / 语言范围。诊断类型固定写「确定性文本特征诊断」，语言范围取自 `DETECTION_SCOPE` 常量。
3. **五项指标卡** —— 助手标注加权占比 / 疑似段落占比 / 非疑似占比 / 疑似段落字数 / 总字数。前三个是百分比，后两个带方括号。
4. **疑似片段分布图** —— 每个片段一根柱子，高度按 `aigcValue` 线性映射（`12 + value × 42` px），颜色三档：`>= 0.75` 红、`>= 0.45` 黄、其余绿。**这是风险分布，不是时间轴**，柱子顺序等于文档顺序。
5. **逐段表格** —— 两列：左「原文内容 + 判定依据」，右「助手标注值」。判定依据由 `report_reason()` 生成，逐条列出该片段命中的风险信号名。
6. **说明区** —— 三条固定声明（见下节）。

---

## 四、PDF 的差异点

PDF 走 reportlab，与 HTML 内容等价但排版受纸张限制：

- 页脚固定写 `aigc-detox-lcw`，不写任何域名或产品名。
- 分布图换成柱状图，图下注一行「柱形越高表示助手标注值越高，颜色由绿到红代表风险升高」。
- 中文依赖 `cjk_font_candidates()` 依序尝试：环境变量 `AI_CHECK_PDF_FONT` → `msyh.ttc` → `simsun.ttc` → `simhei.ttf` → `NotoSansCJK`。全部失败时抛异常并写进 `pdfError`。
- `AI_CHECK_PDF_FONT` 这个环境变量名是继承来的历史命名，**只影响字体路径，不影响任何判定逻辑**。

---

## 五、三条必须原样保留的声明

报告末尾这三句话不是免责套话，是这个工具的定位边界，改写或删除都会造成虚假承诺：

> 本报告给出的是文本特征与改写建议，不是任何平台 AIGC 检测的预测值。数值为助手对文本特征的标注，不是模型概率。
>
> 本报告与知网、维普、Turnitin 或其他闭源平台的检测结果没有对应关系，不得据此推断通过率。
>
> 报告中的"片段"为脚本自动划分，与原文自然段可能不同。

---

## 六、交付给用户时的说法

**可以说的**：
- 「这段命中了『值得注意的是』和『综上所述』两个模板表达」
- 「这一段句长变异系数 0.233，低于 0.30，节奏偏均匀」
- 「这一段有 6 个缓解信号，包括引用编号、定量结果、承认局限，建议只改词不动内容」

**不能说的**：
- 「AI 率 20.73%」
- 「降到了 X% 以下就能过检测」
- 「知网检测大概能过」

原因见 `references/benchmark.md` §九：五家前身里没有一家能预测闭源平台的检测结果，本 skill 也不做这个承诺。

---

## 七、片段（chunk）与自然段的区别

`build_chunks()` 按 `maxCharsPerChunk` 切分正文，一个自然段可能被切成两个片段，两个短段也可能合成一个。表格左列展示的是**片段原文**，不是原始段落。改写阶段（`aigc_detox_lcw_rewrite.py`）匹配用的是 `sourceText` 逐字匹配，与片段边界无关 —— 因此报告里的片段编号只用于定位讨论，不要直接拿去当替换条的 `chunkId` 依据。

排序字段 `importance` 用于提示哪些片段更值得先看，取值来自片段在文档中的位置（摘要、结论等权重更高），与 AI 特征无关。
